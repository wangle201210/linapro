## Why

C1 建好了玩家身份,C2 录入了牛与卡片内容。C3 把寻牛活动的**核心玩法**接通:玩家在小程序地图上看到牛 → 到牛的 GPS 锚点附近拍照激活 → 激活成功获得该牛的校史主卡 → 名字进入共享池(全员可见)与到场序号。这是活动从"内容"走向"可玩"的关键一环,为 C4(喂草/偷草/送草)、C5(排行榜/荣誉)提供激活与卡片数据。

本期交付面向小程序的玩家后端 API(玩家 token 守卫),不实现小程序 UI。无运营后台新页面。

## What Changes

- 新增**可见牛列表(地图)** player API:按放出节奏(阶段/上线时间/可选周几时段)过滤当前可见的牛,返回每头牛的类型、名称、GPS 锚点、**共享池激活态**(全员可见)与**本人是否已激活**。
- 新增**激活核心** player API:
  - **LBS 定位校验**(服务端 Haversine 判距,阈值可配),**不做图像识别**;拍照仅作仪式/取证。
  - **每人每天最多激活 1 只**(按玩家+自然日唯一约束)。
  - **共享池首发并发判定**:事务内对牛行加锁,首位激活者将牛状态 `inactive→active` 并成为首发,记录到场序号;后到者标记非首发。
  - 激活成功**发卡**:玩家获得该牛的主卡(C2 卡片),进入个人图鉴。
- 新增**个人图鉴** player API:玩家已激活牛对应的卡片,按分类浏览(派生自激活记录 + 卡片,不新建权威表)。
- 新增**激活海报** player API:返回海报合成数据(昵称、身份标签、第 N 只牛、随机校史金句、校庆标识);服务端出图(PNG)以可替换接缝提供基础实现。

不在本 change 范围:喂草/签到/偷草/送草(C4)、排行榜/荣誉(C5)、H5 纪念墙(C6)、看板/结算(C7)、铁牛实时定位与加成(C4)。

## Capabilities

### New Capabilities
- `niu-map-activation`: 玩家可见牛列表(按放出节奏)、LBS 激活、共享池首发并发判定、每日激活限次、激活发卡。
- `niu-collection-poster`: 玩家个人图鉴(已激活牛卡片)与激活海报数据/出图。

## Impact

- **后端**:`apps/lina-plugins/sicau-niu/backend/`
  - 新增 `manifest/sql/003-sicau-niu-activation.sql`:激活记录表 `plugin_sicau_niu_activation`(玩家+自然日唯一、玩家+牛唯一、首发/序号、拍照路径);`uninstall/003`。
  - 新增 `api/player`(可见牛列表、激活、图鉴、海报 DTO)、`internal/controller/player`、`internal/service`、`internal/dao`+`model`。
  - `manifest/config`:激活 LBS 判距阈值、海报相关配置。
  - `plugin.go`:在玩家面路由组(C1 player-auth 中间件)绑定 C3 控制器。
- **数据库**:新增 1 张激活记录表;牛的共享池状态复用 C2 `plugin_sicau_niu_niu.status`(事务内原子更新);首发/序号/图鉴均派生自激活记录,无需改牛/卡片表。
- **缓存一致性**:激活改变共享池状态;牛列表为有界数据(≤120),本期用 DB 批量装配读取,缓存策略列入设计(集群下遵循 `cache-consistency`)。
- **i18n**:单语言(中文),不启用 i18n —— 无 i18n 影响。
- **验证**:玩家面 API 无运营后台页面,主要以服务层单测(LBS 判距、首发并发、每日限次、发卡、图鉴、海报数据)+ API 冒烟验证;无新增浏览器 E2E。
