## ADDED Requirements

### Requirement: 微信登录与玩家会话签发
系统 SHALL 支持微信小程序玩家通过登录凭证（`code`）登录：后端经微信网关将 `code` 解析为 `openid`，首次登录自动建档，并签发插件自有的玩家会话 token。玩家身份与宿主管理员/租户用户隔离，使用插件自有玩家表。

#### Scenario: 新玩家首次微信登录
- **WHEN** 小程序提交有效的微信登录 `code`，且该 `openid` 尚无账户
- **THEN** 系统创建玩家账户、签发玩家 token，并在响应中标记为新用户（`isNewUser=true`）

#### Scenario: 老玩家再次登录
- **WHEN** 小程序提交有效 `code`，且 `openid` 已存在账户
- **THEN** 系统返回新签发的玩家 token，并标记 `isNewUser=false`，不重复建档

#### Scenario: 无效登录凭证
- **WHEN** 提交的 `code` 无法被微信网关解析为 `openid`
- **THEN** 系统返回 `bizerr` 鉴权错误，不签发 token

#### Scenario: 开发环境可 Mock 微信网关
- **WHEN** 插件配置启用微信网关 Mock 模式
- **THEN** 登录流程使用 Mock 返回的 `openid`，无需真实微信凭证即可走通全流程

### Requirement: 手机号授权与一机一号
系统 SHALL 支持已登录玩家完成手机号授权绑定，且每个手机号唯一对应一个玩家账户（一机一号）。

#### Scenario: 绑定未占用手机号
- **WHEN** 已登录玩家提交手机号授权凭证，且该手机号未被任何账户占用
- **THEN** 系统解析手机号、绑定到当前玩家，并记录设备指纹

#### Scenario: 手机号已被占用
- **WHEN** 提交的手机号已绑定到其他玩家账户
- **THEN** 系统拒绝绑定并返回 `bizerr` 业务错误，保持一机一号约束

### Requirement: 玩家身份资料维护
系统 SHALL 允许已登录玩家维护身份资料：昵称、身份标签（在校生 / 校友 / 川农好友）、院系（从院系字典选择）、年级（用户填写的正整数）、毕业年（校友填写的年份数字）。身份类型为稳定枚举，由后端命名常量约束取值。

#### Scenario: 在校生资料
- **WHEN** 玩家将身份标签设为「在校生」并选择有效院系、填写年级正整数
- **THEN** 系统校验院系存在、年级为正整数后保存资料

#### Scenario: 川农好友无需院系
- **WHEN** 玩家将身份标签设为「川农好友」
- **THEN** 系统保存资料且不要求院系/年级/毕业年

#### Scenario: 非法身份类型或院系
- **WHEN** 提交的身份标签不在允许枚举内，或所选院系不存在
- **THEN** 系统返回 `bizerr` 参数错误，不保存

### Requirement: 玩家鉴权与自身数据边界
系统 SHALL 通过插件自有玩家鉴权校验玩家 token，并保证玩家只能读写本人数据。响应中的时间点字段 MUST 返回 Unix 毫秒时间戳。

#### Scenario: 携带有效玩家 token 读取本人资料
- **WHEN** 玩家携带有效玩家 token 请求个人资料
- **THEN** 系统返回该玩家本人的资料，时间字段为 Unix 毫秒

#### Scenario: 缺失或无效 token
- **WHEN** 玩家面接口请求缺失或携带无效/过期玩家 token
- **THEN** 系统拒绝访问并返回鉴权错误，不返回任何玩家数据

### Requirement: 运营查询玩家基础信息
系统 SHALL 在运营后台提供玩家基础信息的分页只读查询，受宿主统一权限校验。

#### Scenario: 运营分页查询玩家
- **WHEN** 运营携带 `sicau-niu:player:list` 权限分页请求玩家列表
- **THEN** 系统返回有分页边界的玩家基础信息列表，时间字段为 Unix 毫秒

#### Scenario: 无权限访问被拒绝
- **WHEN** 调用方不具备 `sicau-niu:player:list` 权限
- **THEN** 系统由统一权限中间件拒绝访问
