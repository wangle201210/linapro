## ADDED Requirements

### Requirement: 统一身份能力必须以源码插件交付

系统 SHALL 新增`linapro-uidentity-cas`源码插件承载统一身份 CAS/OAuth 后端能力。插件 SHALL 遵守源码插件目录结构、插件清单、生命周期资源、SQL、后端 API、Controller 和 Service 分层约定。插件不得把业务数据模型写入`lina-core`核心宿主表或宿主私有 DAO/DO/Entity。

#### Scenario: 插件注册统一身份后端路由

- **当** 宿主同步并启用`linapro-uidentity-cas`源码插件时
- **则** 插件注册其后端 RESTful API 路由
- **且** 受保护路由使用宿主认证、租户和权限中间件
- **且** 插件业务数据只写入插件自有表

### Requirement: 插件必须维护统一身份域数据模型

系统 SHALL 在插件 schema 中维护账号、账号详情、单位、容器、分组、应用、账号分组、账号应用授权、账号应用黑名单、分组应用黑名单、密码策略、短信记录、CAS 登录日志、OAuth 日志、OAuth token 和账号变更日志。所有表名 SHALL 使用`plugin_linapro_uidentity_cas_`前缀，并包含必要租户、审计、软删除、索引和唯一约束。

#### Scenario: 重复执行插件安装 SQL

- **当** 插件安装 SQL 被重复执行时
- **则** 表、索引和 Seed 数据创建保持幂等
- **且** 不显式写入自增主键
- **且** 不使用 MySQL 或 SQLite 专有语法

### Requirement: 基础管理 API 必须覆盖统一身份资源

系统 SHALL 为统一身份资源提供基础后端管理 API。资源包括账号、账号详情、单位、容器、分组、应用、账号应用授权、账号应用黑名单、分组应用黑名单、密码策略、短信记录、CAS 登录日志、OAuth 日志、OAuth token 和账号变更日志。列表和详情接口 SHALL 返回前端可直接展示的最小关联投影，避免前端逐行补查。

#### Scenario: 查询账号列表并返回关联投影

- **当** 调用方查询账号列表并按分组、密码强度、状态、关键字或容器过滤时
- **则** 系统在数据库侧完成过滤、排序、分页和租户边界
- **且** 当前页账号的单位、容器、详情和分组名称通过批量查询装配
- **且** 不为每条账号记录单独查询关联对象

#### Scenario: 批量删除资源前校验可见性

- **当** 调用方批量删除任一统一身份资源时
- **则** 系统先校验全部目标记录在当前调用方可见范围内
- **且** 任一目标不可见时整体拒绝
- **且** 删除使用软删除或明确的插件业务删除语义

### Requirement: 账号服务必须支持密码治理

系统 SHALL 支持账号密码强度校验、管理员改密、自助改密、手机号校验改密和账号锁定/解锁。密码策略由插件密码策略表中启用规则决定；未配置启用规则时 SHALL 使用安全默认策略。

#### Scenario: 密码不满足启用规则

- **当** 调用方提交的密码长度、大小写、数字或特殊符号不满足启用密码策略时
- **则** 系统拒绝改密
- **且** 返回结构化业务错误
- **且** 不修改账号密码或密码强度等级

### Requirement: CAS 登录服务必须验证 ticket 并记录日志

系统 SHALL 提供 CAS ticket 校验接口。服务 SHALL 调用配置的 CAS validate URL，解析 CAS XML 响应，按工号匹配插件账号，校验账号状态、应用状态、白名单、账号黑名单和分组黑名单，并记录 CAS 登录日志。

#### Scenario: CAS ticket 校验成功

- **当** CAS validate 返回认证成功且账号、应用和访问规则均允许登录时
- **则** 系统返回统一身份账号和应用的登录结果
- **且** 写入 CAS 登录成功日志
- **且** 日志包含账号、选择账号、应用、IP、浏览器、操作系统、登录时间、登录方式和备注

#### Scenario: CAS ticket 校验失败

- **当** CAS validate 返回认证失败、账号不存在、账号停用、应用停用或命中黑名单时
- **则** 系统拒绝登录
- **且** 写入 CAS 登录失败日志或可诊断记录
- **且** 返回结构化业务错误

### Requirement: OAuth token 和日志必须可治理

系统 SHALL 支持 OAuth token 存储、查询、删除和 OAuth 授权日志记录。OAuth token 记录 SHALL 包含过期时间、授权码、访问 token、刷新 token 和业务数据；日志 SHALL 记录账号、应用、重定向地址和 scope。

#### Scenario: 查询 OAuth 日志列表

- **当** 调用方查询 OAuth 日志列表时
- **则** 系统按数据库侧分页返回结果
- **且** 账号和应用名称通过批量投影装配
- **且** 响应时间字段使用 Unix 毫秒时间戳

### Requirement: 统计接口必须集合化聚合

系统 SHALL 提供统一身份统计聚合接口，返回账号总数、应用总数、认证总数、按容器账号分布、按应用接入方式分布、CAS/OAuth 认证分布、密码强度分布、登录方式分布和应用登录排行。统计 SHALL 使用数据库聚合和批量映射，不得循环查询每个应用或容器。

#### Scenario: 获取统一身份统计

- **当** 调用方请求统一身份统计时
- **则** 系统使用有界数量的聚合查询完成统计
- **且** 容器和应用名称通过批量映射装配
- **且** 不随账号数量或登录日志数量线性增加数据库查询次数

### Requirement: 插件后端必须记录治理影响和验证结果

系统 SHALL 在任务记录中维护本变更的规则读取、i18n、数据权限、缓存一致性、插件、SQL、API、后端 Go、测试和开发工具影响判断。每个实现切片完成前 SHALL 运行对应 OpenSpec 校验、SQL 静态检查、Go 编译门禁和必要单元测试。

#### Scenario: 标记任务完成

- **当** 任一实现任务被标记完成时
- **则** 任务记录包含该任务的影响分析和验证命令
- **且** OpenSpec 严格校验通过或记录明确阻断原因
- **且** 后端 Go 变更至少通过覆盖变更包的`go test`或等价编译烟测
