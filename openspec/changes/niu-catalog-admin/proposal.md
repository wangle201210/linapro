## Why

寻牛活动的一切玩法都围绕「牛 + 卡片」这套内容资产展开:玩家发现/激活的是牛,激活获得的是牛绑定的校史卡片,喂草时随机播放校史金句,铁牛决定喂草加成范围。C1 打好了玩家身份与院系字典地基,C2 接着把**内容资产的数据模型与运营录入**建起来,让运营能在后台配置全校 120 头牛、对应卡片、校史金句和铁牛标识,为 C3(地图/激活)、C4(喂草/铁牛加成)提供数据来源。

本期仍只交付运营后台页面与后端 API(面向小程序的牛/卡片读取接口在 C3 按地图/激活需求提供),不实现小程序 UI。

## What Changes

- 新增**牛(`Niu`)数据模型与运营 CRUD**:序号、类型(普通/特殊)、特殊子类(学院/贡献/校友/精神)、名称、关联院系、GPS 经纬锚点、关联主卡、状态(默认未激活)、**放出节奏**(上线阶段 + 按日期/时段上线规则)。
- 新增**铁牛(`IronNiu`)标识登记与运营 CRUD**:铁牛标识/设备标识(其实时经纬由 C4 从外部 API 拉取,本期只登记标识)。
- 新增**卡片(`Card`)数据模型与运营 CRUD**:分类(人物/事件/科研/院系/精神)、标题、文案、图片;与牛保持「1 牛 1 卡」关联。
- 新增**校史金句(`Quote`)数据模型与运营 CRUD**:供后续喂草/点击随机播放的金句池。
- 牛类型、特殊子类、卡片分类、活动阶段等稳定枚举使用 Go 命名类型与常量(单语言、插件私有、运营不改文案),不引入宿主字典耦合。
- 卡片图片通过宿主文件存储能力上传保存(复用宿主 file-storage 接缝)。

不在本 change 范围:数据看板/统计(M5 看板,留给 C7,依赖 C3 激活数据);牛状态机/激活、地图与可见牛列表(C3);铁牛实时定位与喂草加成(C4);喂草/签到/偷草/送草(C4);玩家端 UI。

## Capabilities

### New Capabilities
- `niu-cattle-catalog`: 牛与铁牛的数据模型、运营后台 CRUD、放出节奏配置与铁牛标识登记。
- `niu-card-catalog`: 卡片(1 牛 1 卡)与校史金句的数据模型与运营后台 CRUD,含卡片图片上传。

## Impact

- **后端**:`apps/lina-plugins/sicau-niu/backend/`
  - 新增 `manifest/sql/` 当前迭代 SQL:`plugin_sicau_niu_niu`、`plugin_sicau_niu_iron`、`plugin_sicau_niu_card`、`plugin_sicau_niu_quote` 建表与索引;`manifest/sql/uninstall/` 对应清理。
  - 新增 `api/`(牛/铁牛/卡片/金句运营 DTO)、`internal/controller/`、`internal/service/`、`internal/dao`+`model/{do,entity}`。
  - `plugin.yaml` 在「寻牛活动」顶级菜单下新增 牛管理/卡片管理/金句管理/铁牛管理 页面与 `sicau-niu:*` 权限按钮。
  - 复用宿主文件存储能力上传卡片图片;复用 C1 院系数据做牛的院系选择。
- **运营后台前端**:新增牛/卡片/金句/铁牛管理页面(LinaPro 插件前端页面)。
- **数据库**:新增 4 张插件自有表(命名以 design/database 规则为准);牛关联 `college_id`(C1)、`card_id`(本期)。
- **i18n**:单语言(中文),插件不启用 i18n —— 无 i18n 影响。
